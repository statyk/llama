# scripts

One-off and campaign tooling. The repo overview is the root `CLAUDE.md`; the llama behaviour these drive is `packages/llama/CLAUDE.md`.

## One-offs

- Stitch a playlist into one mp3: `python3 scripts/stitch_m3u.py <playlist.m3u>`
  (standalone, stdlib-only, needs ffmpeg/ffprobe; stream-copies uniform mp3
  input and re-encodes otherwise, writing ID3 chapters per entry and pulling
  tags from a sibling `manifest.json` when there is one). `scripts` is in
  pytest `testpaths`, so its tests run under plain `pytest -q`.
  `python scripts/backfill_voiced_by.py [--station-root P] [--apply]` is a
  one-off (imports emcee): it fills `dj_audio.presenter` on packages voiced
  before emcee recorded it, by whole-word matching each presenter's `name`
  in the script text — exactly one match writes, zero or several leave `?`.
  Dry run unless `--apply`.
  `python scripts/backfill_tts_record.py [--station-root P] [--apply]` is a
  one-off (imports emcee): it fills `dj_audio.tts` on packages voiced before
  emcee recorded it, for the operator-vouched presenters in its `BACKFILL`
  table only (`phil` voxtral, `jamesbrown` mlx_audio), with `voice:
  "unknown"` (the clone hash is never recomputed). Dry run unless `--apply`.
  `python scripts/backfill_voiced_on.py [--station-root P] [--apply]` is a
  one-off (imports emcee and llama): it dates voiced packages that carry
  neither `dj_audio.voiced_on` nor `voiced_before` from the newest mtime of the
  clips the block names (never the manifest's): inside the NAS-copy window
  (2026-10-10 19:28:00-19:40:00 at -04:00, inclusive; measured 118 packages
  inside, 210 outside) it writes `voiced_before: "2026-10-10"`, else `voiced_on:
  <local date>`; a missing clip leaves the package alone. Raw-JSON, one key,
  and the manifest's old mtime restored with `os.utime` (transmitter reads a
  newer manifest as "changing"); it re-reads the bytes before the replace and
  skips on any change, and under `--apply` refuses while an `emcee` or `llama`
  process runs (a sleeping sweep loop is invisible to that check), and skips a
  package whose block changed since classification. It changes the sha of
  voiced, marked station manifests (136 measured), so `bulk_apply.py unmark`
  refuses those rows with `station copy changed since marking` and that batch's
  reversal is lost for them; `clear-mark` is unaffected. Dry run
  unless `--apply`. Run it BEFORE any re-voice. Before the first `--apply` the
  operator checks that `os.utime` preserves mtime on one scratch file on the
  SMB mount, read back from hugo.
  `python scripts/purge_delivered_audio.py [--config P] [--dest P] [--apply]`
  is a one-off (imports llama): it applies deliver's audio purge, same
  verification, to shows delivered before deliver did it. Dry run unless
  `--apply`.
- `CF_API_TOKEN=… CF_ZONE_ID=… python3 scripts/listeners.py [--hours 24] [--bucket 5m|1h] [--utc]`
  (bucket times print in local time unless `--utc`) estimates listeners from the zone's HTTP analytics (stdlib-only, read-only): `live.m3u8`
  requests per bucket ÷ polls per bucket (10.24 s segments) = `est` concurrent, plus
  `peers` = distinct (IP, user agent); transmitter's own checks and the ops pollers (`OWN_AGENTS`) are excluded; a new
  poller needs its user agent added there or it reads as a listener. Needs a local
  token with Zone Analytics: Read (the Worker's analytics token is account-scoped and
  secret-only). History reaches only as far back as the plan's analytics retention.
- `scripts/station_probe.py race|mtime|cross` is the go-live probe (stdlib-only, Python 3.11-compatible, imports neither emcee nor llama, so it runs on hugo with `python3`; its go-live use is in the programs-and-lineup plan's Task 19). `race --dir D [--n 1000] [--workers 2]` races exclusive create and token-checked unlink on a scratch `.lock-race-<hex>` and prints `acquired/contended/vanished/double/marker-overlap` (exit 0 only on `double 0`; overlap is advisory). `mtime --dir D --create` makes `.mtime-probe-<hex>` (stat it from hugo first), `--replace NAME` rewrites it in the manifest writer's order (temp, flush, fsync, close, `os.utime` to 1767225600, rename, re-check) and prints the epoch, `--remove NAME` deletes it. `cross --dir D --role a|b --n N --tag T [--start-at EPOCH]` runs one side of the race, started on two hosts with the same tag and the same `--start-at` (a future epoch second; each side waits for it, so the runs overlap). It refuses to start (exit 2, naming the file) when `<dir>/.lock-race-<tag>` already exists: a stale file from an earlier run would make every round contended with nothing acquired. Its rounds are paced (a random pause after a refused create and after a release) so both sides take turns. It exits 3 and says so when this side never acquired the lock file (a stale lock file may be present; it names it) or saw no contention (the other side never overlapped): a side's exit 0 means it both acquired and was refused, with `double 0`. A go-live pass is neither side exiting 1 or 2 and at least one side exiting 0 (normally both do). A killed `cross` can leave `<dir>/.lock-race-<tag>` (and `.held-<role>` markers) behind; a clean exit or Ctrl-C removes this side's own, otherwise `rm` them by hand once both sides have stopped. `race` warns on stderr when nothing contended (exit stays tied to `double`) and exits 2 if a worker dies; `--workers` must be >= 2 and `--n` >= 1. The printed line ends with `unreadable <n>` (a contender's read failed with something other than not-found, e.g. EACCES on a delete-pending SMB file). Scratch files are removed in every outcome. Never point it at the station share outside the go-live runbook. Tests: `scripts/test_station_probe.py` (stdlib and pytest only).

- `python scripts/segue_restore_measure.py spot --slugs S... --out DIR [--live]` and `library --out DIR [--limit N] [--seed N]` measure the segue restore pass (spec `docs/superpowers/specs/2026-11-07-segue-restore-design.md`, "Measurement"; own interpreter; tests `scripts/test_segue_restore_measure.py`; `--config P` is a top-level option, given BEFORE the subcommand). Read-only: writes only under `DIR` (replay scratch in `DIR/scratch`, removed) and refuses an `--out` overlapping the library or delivery root. One replay per show gives both arms: a recorder replaces `gather.restore_segues` and calls the real function twice (real donor; `donor=None`), recording arm A (input), arm B (output) and the donor-said-no skips; no rule logic is copied. `spot` replays every named show: stored-`llm` shows with a stub that answers `align_structure` from the stored `show.json` by filename (only these error on a replay alignment that is not `llm` or an arm-A segue differing from stored), stored non-`llm` shows as is with no provider; `--live` uses the configured real providers for all. Writes `spot.json`/`spot.txt`. `library` replays every show with no gather LLM touchpoint, writes `library.json` and prints changed shows and adds, changed by state (library-only / delivered unvoiced / delivered voiced), adds and skips by setlist.fm `info` form, and a seeded stratified sample of 20 adds and 20 skips with the recording's description line.

## Junk-title drop rollout

- `scripts/junk_drop_rollout.py list --arm A --emcee-status S --out DIR [--config P]` (spec `docs/superpowers/specs/2026-11-13-junk-tag-drop-design.md`, "Rollout" step 2; run from the pinned worktree with its own interpreter; tests `scripts/test_junk_drop_rollout.py`) is the read-only membership list: it writes only under `DIR` and refuses (exit 2) an arm whose `sha` is not the running code's (or `-dirty` on either side), a config-fingerprint mismatch, no `delivery_path`, an unreadable or empty station root, and an `--out` overlapping the library or station. Drops are the arm row's `junk_drops` (`drop_source: "replay"`), or for a `needs-llm`/`unreplayable` row `junk_titles.plan_drops` over the current `show.json` (`drop_source: "show.json"`; `overrides.include` honoured, breaker over show.json durations). With a station copy, `audio_reuse.plan_reuse` pairs it (show.json, else `reuse-anchor.json`): a member when a paired source file is a drop, `unpaired` (left out) when nothing pairs and the show has drops; with no station copy, a member when it has a drop. Writes `members.json` (per member: station state `unvoiced`/`voiced`/`not on station`, `presenter` = status `voiced_by`, `backend_now` = `tts_now.backend` / `null` / `"unresolved"`, `clips` = set intros + outro, drops, `held`, `pairs`, `other_differences`), `reapply-replayable.json` and `reapply-needs-llm.json` (predicted lists for `reapply.load_list`, row outcome = the arm row's), and `unpaired.json` (also shows that could not be read); prints counts by station state, voiced by `backend_now`, held, `with-gather-llm wave: N` and unpaired.
- `scripts/junk_drop_rollout.py mark --list DIR/members.json [--config P] [--apply]` (Rollout step 3; same interpreter and tests) is the marking batch, run BEFORE the release binaries are installed. It refuses (exit 2) a list whose `sha`/`config_fingerprint` is not the running code's/config's (or `-dirty`), and an unreadable or empty station root; `--apply` also needs `require_pinned_code` and `require_tools(minimum=JUNK_MARK_TOOLS_FLOOR)` (`2.23.0`, not `CAMPAIGN_MIN_VERSION`). Each member is `MarkItem(slug, "junk-title drop", "gather", row digests)` into batch `<root>/campaign/marking/<sha256(list bytes)[:16]>/` (`inputs.json`: `list`, `list_sha256`, `sha`, `station_root`, `created_at`) via `bulk_apply.mark_apply(skip_voiced=True, no_copy_ok=True)`: under the station lock the copy is re-read; unvoiced (held or not) gets a station and a campaign mark (`marked`), voiced gets the campaign mark only (`voiced: campaign mark only`, `VOICED_CAMPAIGN_ONLY`, no station write, no before copy), not delivered or `no station copy` the campaign mark only, both OK for exit 0. No voiced station copy is ever marked. Both flags default to False (the campaign batch unchanged). The dry run writes nothing and prints `<slug>: <state>[ (held)]: would station-mark | campaign mark only` from an unlocked read. Reverse with `bulk_apply.py unmark --batch <dir>` (processed shows are left and listed).
- `scripts/junk_drop_rollout.py approval --list DIR/members.json --emcee-status S [--config P] [--backend voxtral|mlx_audio|elevenlabs] [--out F]` and `recheck --list DIR/members.json [--config P] <slug>` (Rollout step 6; same interpreter and tests) are read-only (`approval` writes only `--out`, refused when it overlaps the library or station) and refuse (exit 2) the list on the same identity gate as `mark` and an unreadable or empty station root. `approval` re-reads each member's LIVE station manifest: voiced now (whatever the list recorded) gets a block (`presenter`/`backend_now` from the fresh status file, `null`/`unresolved` shown as such; clips from the live `dj_audio`; each drop `'<title>' m:ss held yes|no`; `other_differences`; `library hold flags` from show.json now), under `approvable` or, when show.json has `needs_review`, `held (not approvable)`; recorded voiced but unvoiced now goes under `no longer voiced (unvoiced route)`; a missing (recorded voiced) or unreadable copy or show.json under `cannot check (not approvable)`; `--backend` keeps only voiced members with that `backend_now`; `--out F` gets the approvable slugs one per line. `recheck` prints four `ok`/`FAIL` checks (member of the list; a recorded pair whose `station_file` with `station_title` is in the live station manifest AND whose `source_file` is an `excluded_files` row with reason `junk title`; library show not held; station copy voiced) and exits 0 only when all pass, else 1 with `leave <slug> out of this batch`.

## Adjudicator pilot

- `scripts/adjudicate_pilot.py select|run|compare` (spec `docs/superpowers/specs/2026-11-06-adjudicator-design.md`, "Pilot"; run from the worktree with its own interpreter, only on the operator's go, because trial applies touch real shows; tests `scripts/test_adjudicate_pilot.py`). `select [--n 30] [--seed 20261106] [--out DIR]` is read-only: it stratifies the held shows into the Intent classes (the `ROOT_CAUSE_CLASS`/`FLAG_PATTERNS` tables in the script, prototype verdicts at `~/.llama-harness/t3/verdicts/` first, proportional with a floor of 2), writes `DIR/shows.json` and `population.json`, and prints the absolute show directories one per line (snapshot exactly those before `run`). `run --arm opus|sonnet [--trial-applies 3]` pins `[llm.adjudicate] model` to the arm (never escalates), judges each show once with `force=True, dry_run=True`, records to `DIR/<arm>/<slug>.json` (never `adjudication.json`) and a row per show to `DIR/<arm>/costs.jsonl` (meter read before and after; a re-run skips shows already there); trial applies (restored by the runner) cover every auto switch verdict and the first N other auto verdicts. It refuses (exit 2), by process NAME through `campaign_gate.tool_processes`, while a `llama` or `emcee` process runs. Before EACH show it reads both usage windows and stops cleanly and resumably (one-line reason, exit 3) when the 5-hour window is at/above `--stop-at-5h` (default 85) or the 7-day at/above `--stop-at-7d` (default 80); an unreadable meter, a missing window or a stale `last-known usage` reading (herder returns None for it) also stops, never proceeds. A `RateLimited` stops the same way; a show that vanished or became ambiguous after `select` gets a `failed: ...` costs row and the run moves on. The trial-apply limit counts rows already in this arm's `costs.jsonl` (`trial_kind` switch|other), so a resume does not reset it.  `compare` writes `DIR/compare.md`: a Trial applies section (each trialled show's apply result), judge-only and trial cost rows separately (the full-sweep projection uses the judge-only rows; a row whose 5-hour meter fell is dropped from the point means), a per-show cost table, outcomes and projected held-with-proposal per class and arm, whether the partial-tape classes had any auto path (blocking gate reasons tallied), cross-arm disagreements, agreement with the prototype verdicts, cost and projected full-sweep cost, the strict-surface list and the auto-apply list.
