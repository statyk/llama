## Concerns
1. **The brief's process-check rule misses a running venv `llama` and `python -m llama` on this Mac (measured).** Homebrew's framework Python re-execs, so ps shows a venv console script as `/opt/homebrew/Cellar/python@3.14/.../Python.app/Contents/MacOS/Python /path/.venv/bin/llama get q`, and `python -m llama` as `.../MacOS/Python -m llama status`. The basename `Python` fails a case-sensitive "starts with python" test, and the console script is not a `.py`. I widened, in the refusing direction only: the python test is case-insensitive, and a python whose first non-option argument's basename is `llama` matches. Both measured forms are in test_process_check_matches; every must-not-match line of the brief still does not match (the script's own `.../MacOS/Python scripts/rekey_overrides.py` included). Needs the orchestrator's ack, since it goes beyond the brief's rule.
2. **A sweep loop typed at an interactive prompt is invisible during its sleep.** It runs in the login shell (`-zsh`, no `-c`), so only the `llama` child is seen, and only while it runs; during `sleep 600` nothing matches. The check catches the loop only as `zsh -c '...'`. Runbook step 1 ("stop the sweep loop") stays the primary guard. Wrappers inside a -c string (`nohup llama`, `env llama`, `exec llama`, `time llama`) are not matched either, per the brief's drop set; a wrapper that execs or forks shows its llama child directly.
3. REASONS deviates from verbatim only in spelling out "(below)"; routes keep `<show>`/`k` placeholders rather than the slug (route == REASONS[reason] except the no-CLI-form cases). Say if Tasks 18-20 want the slug substituted.
4. An unreadable show.json is reported as `no show.json` (detail `show.json unreadable: ...`), route the redo; the table has no row for it.
