# Task 16 fix round 1 — findings to fix (orchestrator rulings applied)

Principle (spec, quoted by the brief): status "needs R2 keys for the cloud half; without them, the local half still prints." `status` is the operator's read-only view and is used exactly when something is wrong: no hand-edited, corrupt or partial state document — local or cloud — may produce a traceback or hide unrelated lines. status still writes nothing.

G1 (quality I1). A corrupt or non-dict local `~/.transmitter/alerts.json` crashes status (JSONDecodeError / AttributeError). Fix: factor `Dispatcher._load`'s defensive read into a module-level `alerts.load_state(path) -> dict | None` (None = unreadable) used by both `Dispatcher._load` (unchanged behaviour: unreadable → {} with its warning) and `status_lines`; status prints `alerts     hugo: unreadable (<path>)` when it cannot be read.

G2 (quality I2). `float(raised.get('budget_usd', 0))` crashes on a malformed state/budget.json and shows ignored raises as if in force. Fix: render the raise through `cloudstate.raise_verdict(raised, t_us, period_end_us)` (period end from the guard doc's `period.end` when it parses, else None — reuse whatever the `budget` command does), printing the amount when finite and the verdict reason (honoured / expired / ignored: …). One parse of that document, shared with `budget`.

G3 (quality I3). Mirror the Worker on malformed docs:
- offair: absent → `offair     off`; `offair` a boolean → that value; any other present document (non-boolean `offair`, missing key) → `offair     CORRUPT: the clock treats the station as off the air; rewrite with transmitter offair on|off`.
- guard: when `cloudstate.guard_doc_problem(guard)` is not None, the first guard line is `guard      CORRUPT (<problem>): the clock treats it as a spend trip` (then the remaining guard_summary lines as far as they render).

G4 (quality I4 + spec Minor 1, plan-mandated structure — RULED: fix). `cloud_lines` reads the four keys in one try, so one unreadable/corrupt document blanks the whole cloud half. Fix: read each key separately; a document that cannot be read prints its own line (`<label> unreadable: <exc>`) and the others still print. If the GUARD read fails, say so on the guard line. If ALL reads fail with the same transport error, a single `cloud      unavailable: …` line is fine (keep the brief's test `test_status_without_cloud_access_still_prints_the_local_half` passing — its last line must still be `cloud      unavailable: cannot read state/guard.json: boom`; adjust the shape so that holds, e.g. stop after a first read that fails with a transport/access error, but continue past a corrupt-document error).
Also `cloudstate.get_json`: the `resp["Body"].read()` call sits outside the exception wrapping, so a botocore streaming/read-timeout error escapes as a non-TransmitterError (this also affects `offair`/`budget` — a deferred Task 12 minor). Fix inside get_json: any exception reading the body becomes a CloudStateError ("cannot read <key>: …"), exactly like a failed get_object.

G5 (quality I5 + I4 second half). `cli.status` catches only TransmitterError around `_cloud(config)`; a malformed `endpoint_url` raises ValueError → traceback, nothing printed. Fix: `cli.status` must always print the local half. Catch `Exception` around client construction (message kept: `cloud      unavailable: <exc>`), and make the cloud reader wrapper turn any non-TransmitterError exception into the `unavailable` line too (a read-only view may catch broadly). Do not catch KeyboardInterrupt/SystemExit.

G6 (quality M1 — RULED: fold). With no local epoch, `status_lines` returns `["no epoch yet …"]` before the cloud half. R14 makes the Mac (no workspace) the place to act when hugo is down. Fix: in that branch still append the cloud lines (or the cloud_error line).

G7 (quality M3 — RULED: fold, as tests for G1–G6). One test per corrupt document asserting the local half and the other cloud lines still print: local alerts.json bytes `{not json` and `[1,2]`; budget_usd `"abc"` and an expired raise; offair `{"offair": "true"}` and `{}`; offair.json not JSON (corrupt-document CloudStateError on that key only); guard doc rejected by guard_doc_problem; get_json Body.read raising ConnectionError → CloudStateError; cli.status with a malformed endpoint_url prints the local half and an `unavailable` line (no network: the ValueError is raised at client construction); no-epoch status still shows cloud lines; the cloud-alerts `active` filter (an inactive entry must not be listed). Red first for each fix.
