### New breakage in the fix diff
- Minor, alerts.py `NtfyChannel.send`: the latin-1 predicate is the wrong safety test for ntfy. A non-ASCII latin-1 title (e.g. "café", which the test asserts is sent raw) goes out as the single byte 0xE9. ntfy's `readHeaderParam`/`maybeDecodeHeader` (server/util.go, upstream main) only decodes RFC 2047 (`mime.WordDecoder` with no CharsetReader) and otherwise passes the raw bytes through, so the title arrives as invalid UTF-8 (mojibake). Fix: `if subject.isascii()`, else encode, and flip the "café" assertion. Only a non-ASCII `station_name` reaches this. The default and every code are ASCII.
- Minor, same place: `Header(...).encode()` folds at 76 columns. A long non-ASCII subject (about 45 or more characters) becomes two encoded words joined by `"\n "`, which http.client sends as an obs-fold continuation line. That form is deprecated by RFC 7230, and some front proxies reject it. `Header(subject, "utf-8").encode(maxlinelen=0)` gives a single unfolded word (I checked this on 3.11).
- No other breakage. The code is 3.11-safe (`dataclasses.field`, `email.header`), and no new test reaches the network: the recorder channels are in-memory, urlopen and SMTP are monkeypatched, and the cli test patches `dispatcher_from_config`.

### Out-of-scope observations
- Expected trade-off of item 2, noted for the record: for 5 minutes after every channel has failed, a one-shot event alert (one that does not fire again) is logged only and never sent. Level codes and repeating events are retried on their next fire.
- The cool-down uses `self.now()`, which is wall-clock `time.time`. If the clock steps backward by X, the channel is skipped for X + 300 s. `time.monotonic` for `_failed` would remove this. Negligible on an NTP-slewed host.
