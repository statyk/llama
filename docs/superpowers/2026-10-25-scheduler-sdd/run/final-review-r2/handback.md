## Strengths

- **The strict surface is built the right way round.** `pipeline.Station.extend` (pipeline.py:177-246) treats the persisted rows as history, runs the pure projection, appends one piece at a time, and raises `LayoutError` on any layout it did not expect; `planner.py` keeps exactly the two drop paths (`replan_from`, `cut_for_recovery`); the scheduler module imports no IO. The mutation record for Task 11 shows the four named mutants caught by the named tests (`test_append_only_under_a_clock_edit`, `test_written_rows_always_carry_exact_frames`, `test_appended_rows_obey_the_gap_layout`).
- **Exact counts are enforced structurally, not by convention.** A row is written only from `run2` when its piece is exact, else from `run1`'s pick after `frames_of` measured it (pipeline.py:210-228); `LengthCache` derives "exact" from the same inputs `planned_frames` uses and `length_cache()` rebuilds itself when pause/extra/cache_dir change (pipeline.py:136-146); render re-checks `planned_frames == r.frames` before every encode and `FrameCountDrift` after it.
- **The skip path after a `show_gap_seconds` change is correct and pinned.** The re-plan restarts at the dropped row's *own* start (pipeline.py:229-234, `replan_from`), never `prev.end + new_gap`; `test_scenario_skip_path_after_a_show_gap_seconds_change` renders three segments first, shrinks the gap, kills a later show's encode, and asserts the old rows keep the old gap, the new first row sits at the victim's start, and later rows use the new gap.
- **Continuation closure is designed in, then tested.** `_BlockRun` re-runs the bounded search once per added show and keeps only each run's first show (so the live planner, appending one piece per tick, plays exactly what one projection shows); `_Projection._run_at` reuses the active run only when its layout and `used` set agree with a fresh one (scheduler.py:471-483); `test_appending_first_pieces_reproduces_one_projection` and `test_continuing_*` pin it. My probe (below) extends that to the pipeline's `ahead=1`.
- **Rulings are honoured everywhere I looked**: R5 default-omitting `to_json` (layout.py:58-76); R7 `allow_inf_nan=False`, one-week window bound, `max_shows >= 1` (clock.py:32-37, 118-121); R8/R16 gap 0 disables the rule and the recency term scales over `GAP0_RECENCY_HORIZON_DAYS = 365` (rules.py:51-65); R12 one shared `two_block_ok` with `TWO_BLOCK_MAX_HOURS = 12` used by both `announce.needed` and `_Projection._forms`; R13 fill cause from the block's own start (`_fill_cause`); the operator's accepted Task 8 deviations (surplus `fsum(score-1)`, tier-1 own-count first, no piece twice per block via `_excluded`); R14 frame-anchored `used` (`USED_WINDOW_HOURS = 24`, no `now_us` in `SchedulerInput`); R15 horizon rule and `ahead >= 1`; the Gate-3 single-artist exemption in both `_blocksearch` and `rules.violations` with its regression test; the Task 1b `awaiting_fix` contract (any non-null value is ineligible, malformed never raises, reason capped at 200, `scan_delivered` excludes, render drops an unencoded marked row and lets an on-air one finish); the station-name rulings (player pages + runbook only, alert subjects untouched, cutover step 8 added).
- **Operator-facing views are consistent with each other.** `bends` are attributed to exactly one row per block (`PlannedPiece` docstring, `show()` at scheduler.py:612-616), so `status`'s sum over rows, `report.block_views`' union per block and `aired.jsonl` agree; `miss` lives on the first show row only (`miss=None` elsewhere), which is what `_announcement_broken`, `report` and `status` all rely on; `fill` carries the cause on fill rows for both views.
- **Rollout and rollback are thought through.** Phase-1 rows serialise byte-identically (test pinned), `af46d72` is deployed and tolerant, interstitial rows are skipped by the timeline/site/analysis paths of that build, and the runbook's 7.5 names the right commits in the right order (4fa87a7 → af46d72 → 684d323, confirmed in `git log`). The implicit clock never records a miss (test pinned), so a no-clock cutover is quiet.
- **Honest measurement.** evidence.md names its own defect-and-fix history, discloses the bend undercount and the doubled-17 library artefact, and the floor check (0.0% vs 2.9%) is like-for-like within the caveats it lists.
- Python 3.11 clean (no 3.12-only API or syntax found by grep; the plan's gate ran on Debian 12), no llama/emcee/herder import anywhere under `packages/transmitter`.

#### Minor (Nice to Have)

1. **`ahead=1` equivalence is correct but unpinned.** `pipeline.py:207` relies on "piece [0] does not depend on `ahead`". It holds because `_Occs.at` grows on demand (scheduler.py:311-325) and `last_pos` only gates `_STOP` in `boundary`/`show`, never the Y-landing checks in `_try_next`/`_try_later` (which call `occs.after(x)` and `xrun.complete()` regardless). My probe confirms it: the live loop with `ahead=1` and `ahead=2` produced identical rows on REPRO_CLOCK (67 rows, 6 two-block announcements as piece [0]), DAYCLOCK (61/12), DAYCLOCK without IDs (33/8) and the implicit clock (49). But the suite's `live()` helper (`test_scheduler.py`, `def live`) projects with the default `ahead=2`, so nothing pins the pipeline's value. Fix: have `live()` take `ahead` and run `test_appending_first_pieces_reproduces_one_projection` for both 1 and 2 (or just 1).
2. **Docs say a mid-block cutover "records a MISS"; with no clock file it never does.** `cli.py` (`schedule` docstring), `docs/playout-setup.md` 7.2 ("records a MISS on its first show by design") and 7.4 step 3 ("The MISS therefore lands on the block where that plan ends"), and CLAUDE.md's `schedule` bullet all state it unconditionally, while 7.4 step 4 recommends cutting over with no `clock.toml`, under which `test_implicit_clock_never_records_a_miss` pins that no MISS appears; with a clock file it appears only when the plan end lies outside the entered block's window. An operator following 7.4 will look for a MISS that is not there. Fix: "may record a MISS (only with a clock file, and only when the plan's end lands outside that block's window)". This is the deferred Task 14 minor; cheap, doc-only.
3. **`plan_step`'s start guard is tautological.** pipeline.py:318-321 computes `start = next_start(rows, gap)` and then raises unless `start == rows[-1].end_frame + gap`, which is `next_start`'s definition (planner.py:22-23). It can never fire; the real guard is `extend`'s `expected` check. Either drop it or make it check something independent (e.g. that `start` is not inside an already-rendered segment). Cosmetic.
4. **Cold analysis on the render path is not followed by a watchdog ping until after the encode.** `render_step` calls `st.engine.analyze` directly (pipeline.py:432), not `Station.frames_of`, so a lost `cache/` costs one analysis (146–215 s measured; up to ~8 min on a long show per runbook §5) plus one encode (10–20 min) before the ping at pipeline.py:447-448: under 45 min, so safe, and reachable only after an operator deletes `cache/`. A one-line `self._ping()` after the analyze call would remove the dependency on that arithmetic. Related hugo note, pre-existing class: a render-path re-plan calls `extend` with no `max_new`, so with an estimate-heavy library it can analyse every never-aired pick for the whole lead inside one render step (worst case ~10-15 cold analyses, ~40-55 min); the watchdog is fed per analysis and per projection, so the service survives, but publish waits that long under the plan lock. The lead absorbs it; worth a sentence in the runbook's watchdog paragraph.
5. **`interstitials.scan` stats each clip twice** (interstitials.py:52-55: `p.stat()` for type/size/quiet, then `file_set_key_and_sizes` stats again). R9 asked for one stat per clip; the Task 5 re-review accepted the two-stat form as self-healing. No correctness effect (a clip changing between the two stats gets a key that no longer matches at render and is skipped); noting it only because R9's wording says one.
6. **`DEFAULT_CONFIG_TOML` now writes an uncommented `[interstitials]` table header** (config.py, the template). A config made by `config init` on this build is refused by any build before 684d323 (`extra="forbid"` on an empty table). The runbook's 7.5 covers it ("remove `[interstitials]`"); hugo's live config predates it. Consider commenting the header too, so a fresh config stays rollback-clean without a manual edit.
