### New Breakage in the Fix Diff

1. **Important**, station_lock.py:226-229. The release-side block starts too late. A SIGTERM or SIGHUP that lands after the `with` body ends and before `_block` takes effect raises `SystemExit` from the outer `finally` before `release(held)` runs, and the lock is left behind. That window is the `finally:` entry, `if held is not None:`, and the `_block` call. A second signal arriving while an earlier SystemExit unwinds also hits it. Reproduced: a subprocess patched `_block` to send itself SIGTERM before calling the real `_block` on its second call (the release side). It exited 143, printed "body", and left `.lma-station.lock` (scratchpad `rr1/gap.py`). The same injection on the acquire side leaves no lock, as expected. This is the same window class as cases (ii) and (iii) in finding 1, now on the release side. Suggested shape: make the release in `finally` survive a signal raised in its own prologue. For example, loop `try: mask = _block(); try: release(held); held = None; finally: _unblock(mask)` and, on a BaseException, keep the first exception and retry while `held` is not None, then re-raise. Alternatively, have `_raise_exit` block both signals before it raises, so that once one signal has fired no second one can interrupt the unwind, and catch a BaseException out of the prologue and still release. Add a test like the one above: kill in a patched `_block` before the real block, then assert no lock file.
2. **Minor**, station_lock.py:186-187. This is reasoned from CPython, not reproduced. `signal.pthread_sigmask` calls `PyErr_CheckSignals()` after the syscall (the fix report's own note relies on this for unblock). So a signal already tripped at C level but not yet handled in Python is handled inside `_block`'s SIG_BLOCK call, after the block has taken effect. The SystemExit then propagates before `mask` is assigned, and SIGTERM and SIGHUP stay blocked for the rest of the process. On the acquire side no lock exists yet, and the process is exiting anyway. On the release side this is the same path as item 1. Fixing item 1 so that the block is applied, or the release retried, regardless of where the exception lands also handles it, provided the restore does not depend on `mask` having been assigned. For example, take the old mask with `pthread_sigmask(SIG_BLOCK, [])` before blocking.

Checked and clean: `release` can raise nothing new (FileNotFoundError and OSError are both caught; `token_of` and `holder_text` are unchanged). A refused acquire, and an exception thrown by acquire, both restore the previous mask through the inner `finally`. Off the main thread `_block` returns None and `_unblock` does nothing.
