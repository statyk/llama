## Two deliberate deviations from the brief

1. **`_meter(config, pace)`, not `_meter(config)`.** With `--no-pacing`,
   `decide` returns `Proceed` on any reading, so the brief's signature spends a
   `claude -p "/usage"` subprocess per show on an answer nothing consults.
   `_meter` therefore also gates on `pace.enabled`. Pinned by
   `test_no_pacing_never_reads_the_meter`.
2. **A deferred show is not a boundary.** `except Locked` sets `ran = False`,
   and `record` is skipped. Another run holds that show, so `_process` never
   ran between the two readings: folding that in teaches the gate a zero-cost
   show, and an under-estimate is the direction that walks into the wall (the
   exact reason `observe` refuses rollovers). Pinned by
   `test_a_deferred_show_is_not_a_boundary`, which asserts through
   `pacing_state.read_state` rather than the raw artifact, since "no boundary"
   is equally well expressed by never writing one.

## Concerns for review

1. **The deferred second pass is not gated.** Shows another run held the lock
   on are processed in the `for idx, entry in enumerate(deferred)` pass with
   no gate and no boundary measurement. That is the brief's scope ("inside the
   `for idx, entry in enumerate(pending)` loop"), and the reactive
   `RateLimited` backstop still covers it — one refused show, not a wrong idle
   — but it is a real hole in "never start a show the window cannot finish".
   Widening it changes that pass's `deferred[idx:]` arithmetic, so I left it.
2. **A pre-flight pause never sleeps, even when it would fit.** It goes
   straight to `_checkpoint_pause` per the brief, whereas the per-show loop
   sleeps when `pace.wait` and the wait is under `--max-wait`. So `llama get
   --wait` started twenty minutes before a reset checkpoints instead of
   waiting. Deliberate per the brief; flagging the asymmetry in case Task 8 or
   review wants it closed.
3. **`state` is read once, at pre-flight, then advanced only by `record`.** A
   concurrent run's boundary writes do not reach this run's in-memory
   estimate. Consistent with `pacing_state`'s locked read-modify-write (the
   file is right; this run's copy lags), and cheaper than re-reading per show.
4. No tool refused me at any point.
