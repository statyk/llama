## Short sentences (R6)
- **Units with ≤ 2 comparable words:** 0 of 63, under both models. The shortest unit has 5 words.
- **In the station corpus** of 3904 distinct sentences, only 1 has ≤ 2 comparable words: "Some background first." ("first" is a number word). A further 6 have exactly 3.
  - The sentence splitter folds fragments under 20 chars into a neighbour, which keeps very short sentences rare.
  - **With the recommended MISS_FLOOR of 3, the blind spot grows to n ≤ 3** (7 corpus sentences, 0.18 %).
- **Rule "fail when n ≥ 1 and found == 0":**
  - Clean units it would fail: 0 of 63 for both models (mlx 0/53, Voxtral 0/10). It adds no false alarms.
  - Among non-clean units it catches nothing, because there are none.
  - Of the runaways it catches Chatterbox under Parakeet (0 found). That one is already caught by the miss check. Under Whisper "morning" was heard, so found = 1.
  - It only changes outcomes for n ≤ MISS_FLOOR, where a total mishearing currently passes.
  - The stricter variant "n ≤ 2 and any miss" would also fail 0 clean units, but it has no data behind it and would false-alarm on a two-word proper-noun sentence.
- **My recommendation: adopt the found == 0 rule.** It is strictly additive, threshold-free and showed 0 measured false alarms. It needs a small `transcript_problem` change plus a test, which is a spec deviation, so it is your call. Do not adopt the n ≤ 2 any-miss variant.

## Proposed deviations (for the operator)
1. **Contraction and compound folding in `comparable_words`.** This would be a `verify.py` change, which R9 forbids for me, so it is proposed only.
   - The derived MISS_FLOOR 3 and MISS_FRACTION 0.35 exist only because "Here is" scores as two misses against "Here's", and "L.A." against "LA".
   - The fix: treat a script bigram whose concatenation equals a heard token as found, and the reverse. That covers here+is ↔ heres, you+are ↔ youre, l+a ↔ la, wharf+rat ↔ wharfrat and throw+in ↔ throwin.
   - With it, thresholds would derive at 2 / 0.25 / 4 / 0.25 (estimated by excluding those units; not re-scored), and a 3-word sentence could fail again.
   - **Option A**, the mechanical default, is to adopt as derived: 3 / 0.35 / 4 / 0.25. **Option B** is to fold first, then re-derive. B needs a re-score step, because `--reuse` keeps the saved scores.
2. **The found == 0 rule** (see R6 above).
3. **Parakeet fails a Step 3 check**, so I would not adopt its thresholds or the model itself.

## Recommendation
- **STT model: `mlx-community/whisper-large-v3-turbo-asr-fp16`.**
  - It passes every Step 3 check and is the only one of the two that catches the 0.6B babble runaway by transcript. Parakeet's transcript simply stopped.
  - It smooths disfluencies, as the probe found. That is the right behaviour if Voxtral's ums are wanted: they cannot trigger the extra-words check.
  - Parakeet is about 4× faster (median 0.31 s vs 1.22 s per clip; 2.6 s vs 6.9 s on the 1200-char segment). It derives the same thresholds, has more acronym misses (L.A.), and fails Step 3.
- **Verification for `mlx_audio`: ON, with Whisper.** I hold this weakly.
  - Against: on 53 Qwen takes it caught nothing the guard missed, because no take had a content defect.
  - For: it showed 0 false alarms (LOO and interim), costs about 1.2 s per sentence clip, and is the only defence against a wrong-words take of plausible length. Qwen is unseeded and runs unfiltered.
  - Caveat to weigh: the server peaked at 14 GB on this 16 GB host (most likely during the 1200-char unchunked segment), and Whisper adds about 1.6 GB resident. If memory headroom matters more, OFF is defensible; the guard alone passed every check here.
- **Verification for `voxtral`: OFF for now.**
  - 10 takes, 0 defects and 0 false alarms tell us little (the false-alarm upper bound is about 30 %), and the disfluency question could not be tested because none were heard.
  - Turning it on makes hosted voicing depend on the local mlx server and its preflight.
  - It would be worth revisiting with a larger Voxtral sample that contains disfluencies. Whisper should tolerate them by construction.
- **Thresholds if verification is enabled:** Whisper "all": 3 / 0.35 / 4 / 0.25 under option A, or 2 / 0.25 / 4 / 0.25 after folding under option B. I recommend B if you are willing to accept the `verify.py` change. Otherwise A, which is within every STOP ceiling.
