## How the `run_resume` catch turned out

Not awkward; it fits cleanly, and I did not have to force anything.

I chose **one shared helper**, `_interpret_with_pause(config, ws, req, pace) ->
Criteria | None`, over two copies of the retry loop. Reasons: (1) the retry
loop carries the `stalled` invariant, and two copies of an invariant that
"hangs rather than reddens" when wrong is the exact drift `_render_pause`'s own
docstring records as having cost something before; (2) it mirrors
`_preflight_gate`'s established `proceed=False → caller returns` shape, so the
two call sites read the same; (3) `_interpret_and_stamp` already exists as one
copy for both entry points for the same reason. The scope is the one branch —
`run_resume` is otherwise untouched.

Checkpointing a session that is already `paused` is correct here, not wrong:
`mark_paused` rewrites `resume_after` from the *new* refusal. A re-park that
kept the stale instant would send the operator back to an already-exhausted
window, so I assert the rewrite explicitly
(`info.resume_after.startswith("2026-09-07T14:02")`, replacing the
`07:10:00` the session was parked with). `request.json` survives and
`criteria.json` still does not exist, so the session stays resumable — asserted.
