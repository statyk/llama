## T3-1 — the assertion pins re-entry, at the right line

**Mutant E — `workspace.should_run` → `return True`**, applied in the copy.
- Predicted: the target test fails at the NEW `assert "packaged:" in
  resumed.output`, not at an earlier assertion, with output containing
  "No shows survived winnowing.".
- Observed (isolated run, `--tb=long`): fails at
  `packages/llama/tests/test_sessions.py:477`, the line
  `>       assert "packaged:" in resumed.output, resumed.output`, with
  `assert 'packaged:' in 'pacing: usage read unavailable — pacing on limit
  errors only\nNo shows survived winnowing.\n'`. The three preceding
  assertions (`first.exit_code == 0`, `spent > 0`, `resumed.exit_code == 0`)
  all passed — the resumed run still exits 0 — and the final call-count
  equality is never reached but would also have held. **MATCH.** The new
  assertion is precisely and solely what catches this mutant.
- Captured stdout under the mutant reproduces the finding's mechanism
  verbatim: `winnow: 1 candidates -> 0 after library+ledger -> 0 after
  mechanical`.
- Baseline: the same test passes unmutated in the copy (1 passed).
- Restored; copy re-diffed identical to the worktree.

**Mechanism independently confirmed.** I probed the UNMUTATED resume's output
(temporary `print` in the copy's test file only, reverted immediately):

```
pacing: usage read unavailable — pacing on limit errors only
 1. 1973-06-10  GratefulDead        RFK Stadium                 score 9.5
      monumental Dark Star
packaged: …/shows/gratefuldead-1973-06-10/package
```

No `searching the LMA` and no `winnow: N candidates -> …` line — because
`stages/winnow.py:71` opens with `if not should_run(ws.shortlist, force):
return read_model_list(ws.shortlist, ShortlistEntry)`. So on a healthy
resume the run-level stages skip via their own gate and the persisted
shortlist carries the show back into the per-show loop; only when
`should_run` is broken does `run_winnow` re-execute and let library/ledger
dedup eat the candidate. That is exactly the asymmetry the new assertion
exploits, and it is what makes the assertion a real discriminator rather
than an incidental one.

**Docstring now claims what the test pins.** It names re-entry as the
property, states plainly that a zero call count can hold "for the wrong
reason" if the candidate is dropped before re-entry, and the inline comment
beside the assertion names the alternative short-circuit and the
"No shows survived winnowing." symptom. This matches the ruling ("re-entry
is the spec's own word"). One wording note under Minor below.

## New breakage introduced by the fix diff

**None at Critical or Important.**

Reviewed the diff for regressions on its own terms:
- `sections[""]` is dereferenced directly in both the `elif` and the new
  `phantom_top` line; `_template_keys` always seeds `out = {"": set()}`, so
  no `KeyError` is reachable.
- `phantom_top` correctly does NOT exclude `_FREE_FORM` — `llm`/`tiers` are
  real `Config` fields, so excluding them there would be wrong.
- Section headers of the form `[a.b.c]` inject `a` into `sections[""]`; every
  such `a` in the shipped template is a real `Config` field (the test is
  green), so the new check produces no false positive today.
- The new session assertion sits after the exit-code check and before the
  call-count equality. Order is load-bearing and correct: measured above, the
  mutant reddens at the new line while exit code is still 0.
- No test added or removed (1875 both sides), no production code touched by
  either commit.

### Minor (new, non-blocking, recorded not required)

- 639c6b0's docstring parenthetical "(`run_winnow` runs again, the stages
  walk from the top)" reads two ways. Under "is invoked again", it is
  correct and consistent with the very next clause ("every stage's own
  `should_run` gate finds nothing to do") and with the later clause about
  dedup only firing when `should_run` is broken. Under "re-executes its
