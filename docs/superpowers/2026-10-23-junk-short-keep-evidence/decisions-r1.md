## Migration (section 4, STRICT)

M1 (L, all four reviewers) Loud-failure encoding. Drop the new field names `titles_by_file` / `breaks_after` / `encore_after_file`. Migrated data lives under the LEGACY key names with filename-typed values: `titles: {"<filename>": "<title>"}`, `set_breaks: ["<filename>", ...]` (a break falls after that file), `encore_after: "<filename>"`. A legacy (positional) value is one that parses as an integer (JSON object keys are strings, so a titles key is legacy when it is all digits; every real filename has an extension, so none is all digits — state it). The v2.17.0 model (`dict[int,str]`, `list[int] | None`, `int | None`) rejects every migrated file with a ValidationError, so an old binary, a sweep loop or an old-commit harness arm fails loudly instead of silently dropping overrides. Spec a test that runs e37f670's `Overrides` model (vendored as a fixture) against a migrated file and asserts it raises. A file mixing legacy and filename values is refused by every new-code reader, naming the show.
M2 (L, all four) `set_breaks` presence semantics: absent/None = no structure override; `[]` = forced no breaks (structure-override path, alignment skipped), preserved exactly through the migration. "Has legacy keys" = titles has an int-shaped key, or set_breaks holds an int, or encore_after is an int (an empty `set_breaks: []` needs no re-key and is left as is). `--untitled` / triage `[u]` keep writing `set_breaks: []`. Test on the delmccouryband-2008-05-24 shape (18 titles + `set_breaks: []`).
M3 (L, all four) Undo by recorded hash, not recomputation. On `--apply`, per show, in this order: (1) backup `overrides.pre-rekey.json` written temp + F_FULLFSYNC + rename; (2) the new `overrides.json` written the same way; (3) sidecar `overrides.rekeyed.sha256` holding the hash of the bytes written in (2). Undo restores the backup when the current file's hash equals the sidecar; reports "already undone" (exit 0 for that show) when the current file equals the backup; otherwise refuses naming the show. A successful undo removes the sidecar and the backup. State that undo is only useful together with reinstalling the old binary, and that its post-condition is the old binary's `llama redo <show> --from gather` for any show the new code re-gathered.
M4 (L, s1, s2) Backup rules: an existing backup while the file is still legacy must be byte-equal to the current file or the show is refused.
M5 (L, s2, s1, b1) Refusal checks and route out. Fix the break check so it applies only when a structure key is present (b2). Add a refusal when show.json's kept filenames differ from what the OLD rule (short-keep off) keeps from current metadata + include - exclude (the C1 comparison, reusing its helper). A refused show is repaired with the old binary: before upgrading, the operator keeps a copy of the release as `~/.local/bin/llama-2.17.0`; `llama-2.17.0 redo <show> --from gather`, then re-run the migration. State this route in 4.3.
M6 (L, all four) Ordered runbook in 4.3 (and referenced from 5): stop any `llama run resume --all` loop; copy the old binary to `llama-2.17.0`; install the new release and verify (`which -a llama`, `llama --version`) — the migration script refuses `--apply` unless every `llama` on PATH reports the new version; run any pre-piece-4 base harness arm BEFORE the migration (or on a snapshot of the library taken before it); migrate (dry run, then `--apply`); generate apply lists only from a harness run AFTER the migration (`input_digests` include overrides.json). The migration is a `scripts/` file run with the repo venv's python (`python scripts/rekey_overrides.py`), never via a `.venv/bin/*` console script from a copy.
M7 (L, s1) Guard placement: the legacy/mixed guard lives in the overrides resolver that `compute_gather` uses, so every path (gather, redo, reapply, replay) passes through it. The harness's measurement-only scratch re-key lives only in `scripts/replay_holds.py` behind a harness-only option, and imports the migration's own mapping function (no second algorithm).
M8 (P, s1, b1, b2) Writers: a track number given to `fix`/triage always means the show.json numbering the operator saw (`show --tracks`); the staleness check compares against the overrides as they were before this invocation's own edits; it recomputes through ONE shared helper that returns gather's final kept list (no recomputation of its own). State the behaviour change for `fix --exclude 3 --set-title 7=X` (7 is show.json's track 7) and require a test. `fix --exclude N` (and triage exclusion) on a file that carries a title/break/encore key refuses up front, naming the key and the `--clear-*` flag that resolves it.
M9 (P, b2) A filename key whose file vanished after a metadata-cache refresh: gather fails loudly; document the repair (`--clear-*` must be accepted in that state — say how, or accept a documented hand-edit as the rare limitation; pick the simplest and mark AUTHOR'S CALL).
