# Task 6 code-quality review (t6-qual): Approved

Spec compliance: not judged here (separate seat). Quality verdict below.

### Strengths
- `_narrow_chunk` (packages/emcee/src/emcee/audio.py:187-206) is small, single-purpose and mirrors `_locate_block` (audio.py:292-308) closely enough to read side by side, while differing exactly where the spec says it must: it keeps the WAV takes, raises rather than returns, and has no whole_passage branch. The one-piece guard (audio.py:198-199) re-raises without a call, so no identical refused request is ever re-sent.
- The `try` in `_chunked_pcm` covers only the provider call (audio.py:228-231). WAV parsing, normalization and the gap logic run outside the handler, so a format `SpeechError` from a take is not chained onto the block. The gap condition `j < len(takes) - 1 or i < len(sentences) - 1` (audio.py:244) is correct for both the normal one-take case and the fallback case: a gap between takes, a gap to the next chunk, and none after the last take of the last chunk.
- Each take passes through the same `normalize_speech` call (audio.py:241-242) as any normal chunk, so the fallback gets per-sentence loudness evening with no second code path.
- The tests pin behaviour by exact call sequence and exact PCM length, not mocks. The neighbours test (test_audio.py:1111-1117) checks both the order `[P1, M, M1, M2, P2]` and the length `4*take + 3*gap`, which together catch a dropped chunk, a re-sent neighbour, a missing gap and an extra gap. The process-level tests check the real repair loop end to end: `blocked: "{BLOCKED_S2}"` (test_process.py:707); the reblocked-twice feedback line with `CLEAN_S1 not in feedback` (test_process.py:725-728), which discriminates between a sentence and a whole chunk because the feedback is one line (`process.py:229`, prompt `{{feedback}}`); and no-rephrase on a cross-sentence block (test_process.py:732-744).
- The mutation evidence is sound. Predictions for A-E were written to t6-impl.log (line 278) before the runs. Each observed first failure matches its prediction, and the full runs for A (8 failed) and D (5 failed) include the predicted process-level tests.

### Checks run (named risk -> what I checked)
- **Review Focus 5 (bed + block):** `render_speech_mp3` -> `_render` with `bed_pcm` set -> `_segment_pcm` -> `_chunked_pcm` (audio.py:312-314, 280-281). Narrowing therefore sits on the shared PCM path, and the bed path has no code of its own here. A located block then reaches `render_speech_mp3`'s `if chunking is not None: raise` (audio.py:362-363) and propagates unchanged, as it does without a bed. Test: `test_chunked_block_with_bed_narrows_and_falls_back` (test_audio.py:1133-1144) uses a 24 kHz `_bed_file`. It checks narrowing (text == `_S2`, whole_passage False, calls `[PASSAGE, _S1, _S2]`) and fallback (MP3 out, calls `[PASSAGE, _S1, _S2, _S3]`), the same sequences as the no-bed tests. Mutation A broke it (t6-impl.log line 314). Confirmed.
- **`[tts.verify]` / QualitySpeech on the narrowing calls:** `QualitySpeech.synthesize` (tts/quality.py:44-47) wraps each narrowing call in `_retrying`/`_attempt`, so every kept take is verified and retried once like any take. `SpeechBlocked` passes straight through (quality.py docstring and code: only `SpeechDefect` is caught). A second defect on a take raises `SpeechDefect`, which `_synthesize_dj_audio` tags with the segment (audio.py:463-465) and which fails the package. This matches spec section 5's known limit.
- **A non-SpeechBlocked error during narrowing:** only `SpeechBlocked` is caught (audio.py:204). A transport `SpeechError` propagates with `__context__` set to the chunk block, and `process_package` (process.py:310) does not catch it, so the package fails as a transport failure would anywhere else. Nothing is swallowed.
- **Exception chaining:** `raise located from blocked` (audio.py:205) sets `__cause__` to the chunk-level block. Nothing in emcee/src reads `__cause__`/`__context__` (grep was empty), and the repair reads only `.text`, `.segment`, `.categories` and `.whole_passage` (process.py:225-261, 311). In the one-piece case, `raise blocked` re-raises the exception being handled, which creates no self-referencing context.
- **Sample rate / channels across takes:** framerate, channels and sampwidth come from the first take of the clip (audio.py:235-240) and are not re-checked on later takes. This was already true before this change: neighbour chunks were never cross-checked either. The narrowing takes go to the same provider with the same fmt. Not a regression (see Minor 3).
- **Room tone after a fallback:** the gaps between takes are the same exact-zero 180 ms runs as the gaps between chunks, so `fill_room_tone` (audio.py:247-248, after the loop) fills them identically. Its seed is the full spoken text, so the fallback adds no new nondeterminism beyond the provider's verdict, as spec section 6 accepts. No fallback test runs with room_tone on (all use `_C = Chunking(250, False)`). That is acceptable because the fill preserves length by Task 3's contract.
- **The SpeechBlocked text the repair receives:** providers build `SpeechBlocked(text=<the exact request text>)` (voxtral.py:50, fake.py). The narrowed piece is therefore a sentence of the spoken text, which is the same thing the chunk-equals-sentence path delivered before this change.

#### Minor (Nice to Have)
1. packages/emcee/src/emcee/audio.py:363: the comment `raise  # each chunk is already its own request` is now misleading. A chunk can hold several sentences, and the re-raise is correct only because `_chunked_pcm` has already narrowed the block. The code must stay (spec), but the comment should say so, e.g. `# the chunked renderer already narrowed it (_narrow_chunk)`. The `render_speech_mp3` docstring (audio.py:350-352) still describes narrowing as unchunked-only and could add one clause pointing to `_narrow_chunk`.
2. audio.py:228-231: a fallback is silent. When a chunk ships as per-sentence takes because the filter refused it only in context, nothing tells the operator, even though this is an on-air quality event (different prosody, extra paid calls). A single `detail(...)` line at the catch, such as "content filter refused a chunk; voicing it sentence by sentence", would cost nothing and make spend and quality visible in `emcee run` output. This is optional and the spec does not require it.
3. audio.py:235-240: later takes and chunks are not checked against the first take's framerate, channels and sampwidth. This predates the change, but narrowing adds context-free calls to the set of takes concatenated blindly. A provider that answered a context-free request at a different rate would produce garbled PCM silently instead of raising `SpeechError`. A cheap guard would compare each take's `(rate, channels, sampwidth)` to the first and raise. Low likelihood with Voxtral (fixed 24 kHz).
4. packages/emcee/tests/test_audio.py:1086: `from emcee.audio import _split_sentences` re-imports a name already imported at test_audio.py:29. Drop it. The `_bed` helper (test_audio.py:1128-1130) has a single caller and could be inlined.
5. Coverage gaps (each Minor): (a) no test shows a non-`SpeechBlocked` error during narrowing propagating, e.g. a provider that blocks the chunk and then raises `SpeechError` on piece 2; (b) no fallback test runs with `room_tone=True`; (c) the bed fallback test (test_audio.py:1142-1144) asserts the MP3 header and the calls but not the length of the voice PCM. Because the bed path shares `_chunked_pcm`, (c) is covered indirectly by `test_chunked_fallback_audio_is_the_takes_joined`.

### Assessment

**Task quality:** Approved

**Reasoning:** The narrowing and fallback code is minimal and correctly scoped. It catches only `SpeechBlocked`, never re-sends a neighbour or a one-piece chunk, and puts the takes through the same normalization and gap logic as any chunk. The bed path, the QualitySpeech wrapper and error propagation all behave as the spec requires, and the tests pin exact call sequences and PCM lengths, with mutation evidence that the new rules are load-bearing. The remaining findings are a stale comment and optional hardening.
